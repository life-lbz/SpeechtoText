# 本地语音识别设计

## 浏览器与后端

FastAPI 同时提供静态前端和识别接口。原生 JavaScript 用 MediaRecorder 录制 Chrome 或 Edge 生成的 WebM 音频；录音结束时汇总数据，用与文件上传相同的 multipart 请求提交。等待麦克风授权、录音及识别期间，页面锁定可能冲突的输入操作。录音停止或失败后，统一清理麦克风轨道、计时器、录音事件监听和音量监测。

后端按语言、文件扩展名和实际文件大小校验，使用临时文件进行解码，退出解码阶段后删除文件。标准 PCM WAV 由 Python `wave` 读取并检查帧数；WebM 等格式交给 PyAV，在重采样过程中累计采样数。达到时长上限时提前终止，避免将整段超长音频放入内存。两条路径均交付 16 kHz 单声道 float32 波形。

## 模型与错误处理

默认使用 faster-whisper 的多语言 `base` 模型，推理配置为 CPU INT8。该模型同时支持普通话和英语，量化配置降低了普通 CPU 的推理与内存负担。PyAV 与 CTranslate2 随 Python 依赖安装，浏览器录音可直接解码。模型固定使用用户选择的语言进行转写，并启用语音活动检测。

默认启动时加载一次模型。可选择在首个有效识别请求时加载，重复加载由锁保护。懒加载耗时从响应的处理耗时扣除。解码与推理运行在线程池，单进程的 CPU 模型将推理串行化，单次推理失败时重试一次。客户端收到的错误包含可执行的提示，服务日志记录定位所需的异常和请求编号。

静态资源由本机服务提供，权重准备后可使用 `HF_HUB_OFFLINE=1` 启动。用户音频只发往这个 FastAPI 服务，项目没有识别历史存储。
