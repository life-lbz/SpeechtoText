# 测试报告（2026-11-19）

## 1. 环境与执行方式

- Windows 11 x64，Python 3.12.16，Chrome。
- faster-whisper small，CTranslate2 4.6.0，CPU INT8，4 个推理线程。
- 按 README 的命令安装和启动；运行不需要 Node.js、GPU、Docker 或数据库。
- 常规 pytest 使用模型替身；浏览器验收使用真实本地模型，二者严格区分。

## 2. 自动化测试

执行：`python -m pytest -q`。

实际结果：**46 passed in 1.57s**，原始输出见 `evidence/pytest.log`。

覆盖健康检查、正常和非法请求、中英文语言参数、空文件、无法解码、不支持格式、音频处理、模型调用、模型加载失败与推理失败。设置 `HF_HUB_OFFLINE=1` 后执行，不需要真实麦克风，也不会触发模型下载。

## 3. 真实本地模型与浏览器验收

执行方式见 README。服务设置 `HF_HUB_OFFLINE=1`，模型从本地缓存加载；Chrome 阻断所有非本地请求。录音通过浏览器 `getUserMedia` 和 `MediaRecorder` 完整链路执行，输入由仓库样本模拟。

| 场景 | 实际结果 |
| --- | --- |
| 中文 WAV 上传 | 8.14 秒，HTTP 200，识别文本与人工参考一致，复制成功 |
| 英文 WAV 上传 | 7.27 秒，HTTP 200，识别文本与人工参考一致，复制成功 |
| 中文录音实时预览 | 停止前至少两次预览更新；9.72 秒录音生成终稿，处理 3.12 秒 |
| 英文录音实时预览 | 停止前至少两次预览更新；9.72 秒录音生成终稿，处理 2.31 秒 |
| 预览请求 HTTP 503 | 显示降级提示，完整录音仍成功生成终稿 |
| 60 秒自动停止 | 60.33 秒自动停止，实际音频 60.00 秒，仅一次终稿请求，CPU 处理 49.12 秒 |
| 麦克风权限拒绝 | 显示可理解的权限原因，页面可继续操作 |
| 授权等待与录音中断 | 等待时锁定冲突操作，中断后释放轨道并允许重试 |

机器可读结果见 `evidence/browser-real.json`。模拟输入会循环播放样本，因此长录音出现重复句子属于音源特征，不用于评价真实长访谈准确率。

### 实时预览结论

实时预览由持续采集麦克风、约 4 秒音频分片、后端本地 ASR、停止前持续更新页面和停止后完整终稿组成。该方案属于短分片近实时识别，不使用模型原生流式推理，延迟和准确率以实际 CPU 推理结果为准。

## 4. 测试样本

`samples/chinese.wav` 和 `samples/english.wav` 分别为 8.14 秒和 7.27 秒。两份音频均由 Windows 系统语音自主合成，只包含通用中英文句子，不含敏感个人信息，可随本项目使用和分发。人工参考文本及来源说明见 `samples/reference.txt`。

## 5. 已知边界

- 数字静音门限不是完整 VAD，噪声、分段边界和口音仍可能导致错词；结果需要人工校对。
- 实时延迟为约 4 秒采集加 CPU 推理与排队，不宣称商业级即时字幕性能。
- 本次验证的麦克风输入由 Chrome 使用仓库样本模拟，未宣称完成物理麦克风的人工录音。
- 本次验证通过本地缓存、HF 离线设置和浏览器外部请求阻断确认无外网依赖，未宣称完成系统网卡断开的硬件级测试。

如需严格完成物理环境人工复核，只需按 README 启动后分别用物理麦克风录制中英文，并在模型缓存准备后断开外网重复上传与录音；无需修改代码。
