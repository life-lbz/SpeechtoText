# 测试报告

验证日期为 2026-11-17。后端运行于 Windows 11 x64、Python 3.12.16，使用 faster-whisper 1.2.1、多语言 `base` 权重及 CPU INT8。浏览器验收使用本机 Chrome，通过 `127.0.0.1:8000` 访问服务。

## 常规自动化测试

运行 `python -m pytest -q`，36 项通过。模型层使用替身，WAV 和 WebM 使用实际解码器。覆盖首页、健康检查响应、正常中英文参数、非法参数、空文件、损坏音频、不支持格式、超过 10 MiB、超长 WAV 和 WebM、解码失败时跳过加载、懒加载失败后的重试，以及推理重试和文本处理。

## 真实模型与浏览器验证

浏览器脚本向 Chrome 的模拟麦克风送入仓库 WAV，页面自行录制、提交 WebM，并展示真实模型结果。以下为同一轮带 60 秒检查的实测数据，处理时间会随机器和模型热身状态变化。

| 场景 | 音频时长 | 服务端处理耗时 | 结果 |
| --- | ---: | ---: | --- |
| 上传中文 WAV | 4.87 秒 | 1.03 秒 | HTTP 200，输出「你好,欢迎使用本地语音识别系统。」 |
| 上传英文 WAV | 3.92 秒 | 0.57 秒 | HTTP 200，输出「Hello and welcome to the local speech to text system.」 |
| 浏览器录制中文 WebM | 5.22 秒 | 0.59 秒 | HTTP 200，页面显示与样本一致的文本，逗号样式有差异 |
| 浏览器录制英文 WebM | 4.20 秒 | 0.57 秒 | HTTP 200，页面显示与样本一致的文本 |
| 持续录制至 60 秒 | 60.00 秒 | 2.00 秒 | 自动停止，发起一次识别并返回 HTTP 200 |

Chrome 拒绝麦克风权限时出现预期提示。复制按钮写入的文字与页面转写结果一致。另一次故障注入验证了等待授权时输入被锁定、录音中断后麦克风轨道结束，以及页面恢复到可再次录音和上传的状态。

离线验证使用 `HF_HUB_OFFLINE=1` 和现有缓存。另在后端 Python 进程内阻断外部连接，并通过实际 API 验证懒加载前为 `standby`，首个请求加载真实模型后为 `ok`，中英文 WAV 均转写成功。中文耗时 0.66 秒，英文耗时 0.57 秒，首次加载约 0.8 秒已排除在计时之外。

## 人工验收清单

使用 [README](../README.md) 的启动命令，在 Chrome 中执行以下步骤并记录结果。

1. 用物理麦克风录制一段普通话，手动停止并核对页面结果。
2. 切换英语，用物理麦克风录一段英文，手动停止并核对页面结果。
3. 通过文件选择框上传两份 WAV，与 [人工参考文本](../samples/reference.txt) 对照。
4. 在浏览器站点权限中阻止麦克风，然后尝试录音，检查权限提示并恢复权限后重试。
5. 准备好模型后断开外部网络，依次验证上传识别和浏览器录音识别。

本轮已通过自动化验证浏览器上传、模拟录音、权限拒绝、复制和 60 秒上限。物理麦克风、人工断网、干净环境首次下载，以及切到后台标签页后的计时均待补验。浏览器长时间挂起可能延迟自动停止，超出容差的音频会由后端拒绝。模拟麦克风在长时间测试中循环播放样本，因此转写会包含重复的参考语句。
